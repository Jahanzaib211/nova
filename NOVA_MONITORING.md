# Nova Observability Stack

Enterprise-grade monitoring for the Nova/DeerFlow platform: full-stack visibility from edge (Cloudflare tunnel) through nginx → gateway → sandbox/browser subsystem, all via loopback-bound Grafana + Prometheus + Loki + Alloy + Blackbox + Uptime Kuma.

> **Runbook authority**: this file is the single source of truth. Update it whenever you change the stack topology, ports, dashboards, SLOs, or instrumented code paths.

| `alloy` | `127.0.0.1:12345` | self-metrics |
| `grafana` | `127.0.0.1:3002` | self-metrics |

Blackbox scrape pattern (`prometheus.yml`):
```yaml
- job_name: blackbox
  metrics_path: /probe                 # must be /probe, not /metrics
  params: { module: [http_2xx] }      # module NAME goes in params
  static_configs:
    - targets:
        - http://127.0.0.1:2026/health  # FULL URL as the static address
  relabel_configs:
    - source_labels: [__address__]
      target_label: __param_target      # forward URL to /probe?target=
    - source_labels: [__param_target]
      regex: 'http://127.0.0.1:2026/health'
      replacement: 'nova-internal-health'
      target_label: instance
    - target_label: __address__
      replacement: '127.0.0.1:9115'    # rewrite target to blackbox exporter
```

> ⚠️ Common mistake that was fixed: do **not** put `module=http_2xx` in the static_config __address__ — that would be confused with the URL. Also do NOT use `metrics_path: /metrics` — blackbox only runs probes at `/probe`.

### 6.1 Key Loki config (`docker/monitoring/loki/loki.yaml`)

```yaml
common:
  instance_addr: 127.0.0.1
  path_prefix: /loki             # controls storage paths ONLY (not HTTP API)
  storage: { filesystem: { chunks_directory: /loki/chunks, rules_directory: /loki/rules } }
  replication_factor: 1
  ring: { kvstore: { store: inmemory } }

schema_config:
  configs:
    - from: "2026-01-01"
      store: tsdb
      object_store: filesystem
      schema: v13
      index: { prefix: index_, period: 24h }

limits_config:
  retention_period: 720h                          # 30 days
  reject_old_samples: true
  reject_old_samples_max_age: 168h
  allow_structured_metadata: true                  # required for Alloy push
  ingestion_rate_mb: 10
  ingestion_burst_size_mb: 20

compactor:
  retention_enabled: true
  working_directory: /loki/compactor
```

### 6.2 Loki 3.5 → 3.6 upgrade (LOKI 3.7 REMOVED PROMETHEIL PUSH)

Loki 3.5.0 silently rejects Alloy/Loki-bridge pushes with `negative structured metadata bytes received`. Loki 3.7.0 removed the Promtail/Alloy-compatible push protocol entirely.

**Use `grafana/loki:3.6.12`** — the last release with the Alloy push support. The `allow_structured_metadata: true` flag is required.

### 6.3 Query API gotcha

All Loki HTTP routes are prefixed with `/loki/api/v1/...`. The `path_prefix` YAML field controls **storage paths**, NOT API paths. Examples:
```
http://127.0.0.1:3100/loki/api/v1/push     ← push endpoint
http://127.0.0.1:3100/loki/api/v1/query    ← instant query
http://127.0.0.1:3100/loki/api/v1/query_range
http://127.0.0.1:3100/loki/api/v1/labels   ← list all label names
http://127.0.0.1:3100/loki/api/v1/label/<name>/values  ← values for a label
```

Timestamps in queries are **nanoseconds** since epoch. Use `date +%s%N` in shell, not `date +%s`.

### 6.4 Forbidden LogQL patterns

- `__error__=""` — Loki rejects empty-string label filters. Use `__error__!~".+"` or drop the filter.
- `field != ""` (e.g. `status_class != ""`) — same restriction. Drop the filter and rely on the parser producing no rows when the label is missing.
- `last_over_time(<textField>[5m])` without `unwrap` — `last_over_time` works on numeric metric streams. For text-string labels use `sum(count_over_time({label="value"}[5m]))` instead.
- `| json | name="..."` with parsed-array fields — `| json` parses only the top level, not nested arrays.

## 7. Instrumented Code Paths

The following call sites in `backend/packages/harness/deerflow/sandbox/` were wired so the counters in `sandbox/metrics.py` actually fire on production traffic. Without instrumentation, `browser_check_total`, `circuit_state_transitions_total`, and `retry_attempts_total` are declared as HELP/TYPE only — Prometheus would still see them but with no values.

### 7.1 `browser_check.py` → `_run_browser_check_unlocked`
On every entry, captures `time.monotonic()` and increments `browser_check_total{outcome=...}` + observes `browser_check_duration_ms{engine=...}` on return. **Outcome labels**:
- `ok` — all routes passed
- `issues` — at least one route failed
- `no_browser` — local sandbox (no Playwright), no tool calls expected

### 7.2 `browser_circuit_breaker.py` → `_transition`
On every CLOSED→OPEN / HALF_OPEN→CLOSED / HALF_OPEN→OPEN transition, increments `circuit_state_transitions_total{from_state, to_state}`. Errors are caught + debug-logged — never propagate.

### 7.3 `browser_retry.py` → `retry_browser_call`
At every terminal branch, increments `retry_attempts_total{outcome=...}`. **Outcome labels**:
- `succeeded` — terminal success (any attempt)
- `circuit_open` — short-circuited because breaker was already OPEN
- `permanent` — fail-fast on permanent error (not transient)
- `gave_up` — non-browser exception (unexpected error masked)
- `transient_attempt` — non-terminal transient error (paired with eventual terminal)
- `exhausted` — terminal: all retries exhausted

**Also**: the async counterpart `retry_browser_call_async` re-uses `guard_browser_call` so circuit-breaker bookkeeping is symmetric.

### 7.4 The full registry (`sandbox/metrics.py`)

| Metric | Type | Labels | Cardinality |
|---|---|---|---|
| `browser_check_total` | counter | `outcome` | 3 |
| `browser_circuit_state_transitions_total` | counter | `from_state`, `to_state` | 9 |
| `browser_retry_attempts_total` | counter | `outcome` | 6 |
| `browser_screenshot_total` | counter | `outcome` | 3 (already instrumented at `workspace_tools.py:776-829`) |
| `browser_circuit_open_count` | gauge | – | 1 |
| `browser_check_duration_ms` | histogram | `engine` | 2 |
| `igino_search_total` / `igino_fetch_total` / `igino_research_total` | counter | `outcome` | 3 each |
| `igino_cache_hits_total` / `igino_cache_misses_total` | counter | `source` | low |
| `igino_search_duration_ms` / `igino_fetch_duration_ms` / `igino_research_duration_ms` | histogram | `source` | low |
| `igino_tor_available` | gauge | – | 1 |

Total cardinality: ~80 series. Hand-rolled (no `prometheus_client` dep), zero-side-effect on import.

## 13. Known Caveats

### 13.1 Port collision workarounds
- Host port **3001** occupied by an external node process → **Uptime Kuma is on `127.0.0.1:3003`** (set via `UPTIME_KUMA_PORT=3003` env var). `/health` mapped to `127.0.0.1:3003`.
- Prometheus + Loki + Grafana all use `network_mode: host` so the per-container config is the same as the host.

### 13.2 Cloudflare tunnel / dashboard wiring
Public tunnel routes were added (`nova.alilabsx.com` → :2026 frontend, `dash.alilabsx.com` → :3002 Grafana, `status.alilabsx.com` → :3003 Uptime Kuma). Cloudflare Access email-OTP gates all three. After updating `config/cloudflared-nova.yml`, restart with `cloudflared tunnel restart` (not `cloudflared` reload — the tunnel needs re-handshake for ingress changes).

### 13.3 Disk usage / retention
- Prometheus: 30-day retention (`--storage.tsdb.retention.time=30d`)
- Loki: 30-day retention (`limits_config.retention_period: 720h`) + compactor enabled
- Grafana: provisioning under `/etc/grafana/provisioning/` (read-only). Per-tenant DB at `/var/lib/grafana/grafana.db` (1.1 MB). Beware: Grafana uses bbolt for sessions + dashboards.

### 13.4 Boot-time failures to ignore
`up{job="llama-server"} == 0` (down) is **expected**: the llama-server launcher hasn't yet wired `--metrics`. The `make monitoring-verify` step 02 counts `health=up` — currently 9 of 10 — and that's the right count.

### 13.5 Single-node / dev-only
- Single Prometheus, single Loki → no HA. If Prometheus crashes, recording rules / alerts are lost.
- No auth on Prometheus or Loki (loopback-only, so the assumption is "trust the host").
- Grafana anonymous auth is disabled (`GF_AUTH_ANONYMOUS_ENABLED=false`).
- Cloudflare Access is the only boundary on the public side.

## 16. Troubleshooting Playbook

| Symptom | Check |
|---|---|
| Dashboard panels show "No data" | 1. Verify the panel's `datasource` is set explicitly (Prometheus vs Loki). <br>2. Verify the query returns data via `curl :9090/api/v1/query` or `curl :3100/loki/api/v1/query_range`. <br>3. Check the Grafana console for parse errors. |
| Loki returns "parse error: unexpected $end" | The query has unbalanced braces or an unsupported syntax (`__error__=""`, `field != ""`, `last_over_time(<text>)`). See §6.4. |
| Loki returns "negative structured metadata bytes received" | Loki 3.5.0 bug. Upgrade to `grafana/loki:3.6.12` and ensure `allow_structured_metadata: true`. |
| Blackbox target shows up=0 with no errors in `up{job="blackbox"}` | Wrong `metrics_path` (`/metrics` vs `/probe`) or wrong `module` / `target`. Re-check the relabel logic in §5. |
| Grafana login returns 401 even with correct password | The `grafana.db` was initialised before the env var `GF_SECURITY_ADMIN_PASSWORD` was set. Either regenerate via `gf_reset_admin_password` (`/etc/grafana/provisioning/` doesn't help), or delete `/var/lib/grafana/grafana.db` and let Grafana recreate. |
| Uptime Kuma refuses to start | Host port 3001 is occupied by another process. Confirm `UPTIME_KUMA_PORT=3003` in the compose env. |
| PM2 `nova-monitoring` exits immediately | `~/.config/nova/monitoring.env` doesn't exist or is unreadable. Check `pm2 logs nova-monitoring`. |
| No counters in Prometheus for `browser_*` | Gateway process is still running with old code (no instrumentation). Restart PM2 app `deerflow` so `--reload` re-imports the new modules. |
| Cloudflare tunnel refused dashboard | Email-OTP step. Cloudflare Access is the boundary, not the Grafana session. |
