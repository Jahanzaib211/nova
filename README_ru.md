**Nova** — это полностековый **компьютерный агент**, который исследует, программирует и создаёт. Он оркестрирует **субагентов**, **память** и **песочницы по потокам** для выполнения практически любых задач — на базе **расширяемых навыков** и живого потокового просмотра собственного компьютера агента: терминал, редактор, предпросмотр браузера и прогресс задач, всё в реальном времени.

Nova построен **[Ali Technologies](https://www.alilabsx.com)** на базе open-source фреймворка [DeerFlow](https://github.com/bytedance/deer-flow). Лицензия MIT upstream и все оригинальные уведомления об авторских правах сохранены — см. [Лицензию](#лицензия) и [NOTICE.md](./NOTICE.md).

> Скажите привет: *"Я — Nova, компьютерный агент."*

![Рабочее пространство Nova — агент строит калькулятор чаевых и показывает его в реальном времени во вкладке Браузер Agent's Computer](./docs/images/nova-workspace.png)

## Что Nova добавляет поверх DeerFlow

Nova — это полностековый рефакторинг DeerFlow 2.0 — **120 533 строки нового кода в 698 новых файлах**, при общей дельте **+145 947 / −11 844 в 1 148 файлах**. Из 1 338 файлов апстрима на момент форка 884 (66 %) не тронуты. Аудит от 2026-09-08; каждое число воспроизводимо, а точные команды — включая то, какие сгенерированные артефакты исключены и почему — приведены в **[NOVA_VS_DEERFLOW.md](./NOVA_VS_DEERFLOW.md)**.

Основные добавления, все построены для Nova:

- **Agent's Computer** — 6-вкладочная панель в реальном времени (Терминал, Редактор с красным/зелёным live-diff, Предпросмотр браузера, Таймлайн активности, Файлы, Ревью), показывающая что делает агент в реальном времени.
- **Петля верификации** — агент тестирует свои сборки: headless Chromium проверяет работающий dev-сервер (ошибки консоли, обнаружение пустого рендера, скриншоты), автоматически запускается при готовности dev-сервера и на поставляемом HTML, с визуальным путём чтобы модель *видела* свою сборку.
- **Детерминированное ревью кода** — движок ревью без LLM, выдающий вердикт на простом английском для не-программистов плюс статистика и флаги рисков по файлам для разработчиков.
- **Самокорректирующие middleware** — бюджеты итераций на уровне рантайма, обнаружение dead-end циклов, предварительная проверка квот, де контаминация ошибок, прогресс задач в реальном времени.
- **32 инструмента агента** — shell-сессии, навигация/клик/ввод/eval браузера, скриншоты, scaffolding, жизненный цикл dev-сервера, dev_verify, code_review, сохранение навыков и др.
- **iGIN0 приватность** — укреплённый клиент SearXNG с retry, автоматическим выключателем, LRU+TTL кэшем, опциональным маршрутизацией через TOR и аудит-трейлом приватности.
- **Управление моделями на лету** — добавляйте/переключайте модели через API и UI настроек без редактирования конфигов.
- **Ops-слой** — самовосстанавливающийся watchdog с 11 зондами, жизненный цикл Docker под управлением PM2, персистентность после перезагрузки.
- **Локальные + бесплатные модели через LiteLLM** — пресет Ollama в настройках и прокси LiteLLM под управлением PM2, предоставляющие четыре бесплатных облачных модели Ollama (MiniMax M3, Nemotron 3 Super, Qwen3 Coder 480B, GPT-OSS 120B) наряду с платными провайдерами.
- **8 112 строк новых тестов** в 37 новых файлах тестов бэкенда.

Upstream DeerFlow предоставляет фреймворк агента (субагенты, память, LangGraph рантайм), систему навыков и песочницы Docker по потокам — заслуга upstream. Полная, воспроизводимая карта атрибуции в **[NOVA_VS_DEERFLOW.md](./NOVA_VS_DEERFLOW.md)**.

- **Трек 1 агент** — компактный, экономный по токенам Fireworks batch-harness в [`hackathon/track1/`](./hackathon/track1/); соберите и протестируйте через `make hackathon-track1`.

## Настройка Агента в Одну Строку

Если вы используете Claude Code, Codex, Cursor, Windsurf или другой coding-агент, можно передать ему инструкции по настройке одним предложением:

```text
Help me clone Nova if needed, then bootstrap it for local development by following https://raw.githubusercontent.com/Jahanzaib211/nova/main/docs/Install.md
```

Этот промпт предназначен для coding-агентов. Он говорит агенту клонировать репозиторий при необходимости, выбирать Docker если доступен, и останавливаться с точной следующей командой плюс любые недостающие конфиги.

## Быстрый Старт

### Конфигурация

1. **Клонируйте репозиторий Nova**

   ```bash
   git clone https://github.com/Jahanzaib211/nova.git
   cd nova
   ```

2. **Запустите мастер настройки**

   Из корневой директории проекта (`nova/`):

   ```bash
   make setup
   ```

   Это запускает интерактивный мастер, который помогает выбрать LLM-провайдер, опциональный веб-поиск и предпочтения выполнения/песочницы. Генерирует минимальный `config.yaml` и записывает ключи в `.env`. Занимает около 2 минут.

   В любой момент запускайте `make doctor` для проверки настройки и получения подсказок по исправлению.

### Запуск Приложения

#### Размер Деплоя

| Цель деплоя | Точка входа | Рекомендуется | Примечания |
|---------|-----------|------------|-------|
| Локальная оценка / `make dev` | 4 vCPU, 8 ГБ RAM, 20 ГБ SSD | 8 vCPU, 16 ГБ RAM | Для одного разработчика или лёгкой сессии |
| Docker разработка / `make docker-start` | 4 vCPU, 8 ГБ RAM, 25 ГБ SSD | 8 vCPU, 16 ГБ RAM | Сборки образов и монтирования требуют больше места |
| Долговременный сервер / `make up` | 8 vCPU, 16 ГБ RAM, 40 ГБ SSD | 16 vCPU, 32 ГБ RAM | Предпочтительно для совместного использования |

#### Вариант 1: Docker (Рекомендуется)

**Разработка** (hot-reload, монтирование исходников):

```bash
make docker-init    # Скачать образ песочницы (только первый раз или при обновлении)
make docker-start   # Запустить сервисы (авто-определение режима из config.yaml)
```

> [!TIP]
> В Linux, если Docker команды падают с `permission denied`, добавьте пользователя в группу `docker` и перелогиньтесь. Полное исправление в [CONTRIBUTING.md](CONTRIBUTING.md#linux-docker-daemon-permission-denied).

**Продакшен** (сборка образов локально, монтирование конфигов и данных):

```bash
make up     # Собрать образы и запустить все продакшен-сервисы
make down   # Остановить и удалить контейнеры
```

Доступ: <http://localhost:2026>

#### Вариант 2: Локальная Разработка

1. **Проверить зависимости**:

   ```bash
   make check  # Проверяет Node.js 22+, pnpm, uv, nginx
   ```

2. **Установить зависимости**:

   ```bash
   make install  # Устанавливает backend + frontend зависимости + pre-commit хуки
   ```

3. **Запустить сервисы**:

   ```bash
   make dev
   ```

4. **Доступ**: <http://localhost:2026>

### Продвинутое

#### Режим Песочницы

Nova поддерживает несколько режимов выполнения в песочнице:

- **Локальное выполнение** (код выполняется напрямую на хосте)
- **Docker выполнение** (код в изолированных Docker-контейнерах)
- **Docker + Kubernetes** (код в Pod'ах через provisioner сервис)

См. [Руководство по Конфигурации Песочницы](backend/docs/CONFIGURATION.md#sandbox).

#### MCP Сервер

Nova поддерживает настраиваемые MCP-серверы и навыки для расширения возможностей. HTTP/SSE MCP-серверы поддерживают OAuth-токены (`client_credentials`, `refresh_token`). См. [Руководство по MCP Серверу](backend/docs/MCP_SERVER.md).

#### IM Каналы

Nova поддерживает получение задач из мессенджеров. Каналы запускаются автоматически при настройке — публичный IP не требуется.

| Канал | Транспорт | Сложность |
|---------|-----------|------------|
| Telegram | Bot API (long-polling) | Легко |
| Slack | Socket Mode | Средне |
| Feishu / Lark | WebSocket | Средне |
| WeChat | Tencent iLink (long-polling) | Средне |
| WeCom | WebSocket | Средне |
| DingTalk | Stream Push (WebSocket) | Средне |

Настройте в `config.yaml` и задайте соответствующие API-ключи в `.env`.

#### Трассировка LangSmith

Nova имеет встроенную интеграцию с [LangSmith](https://smith.langchain.com). При включении все LLM-вызовы, запуски агентов и выполнения инструментов трассируются и отображаются в дашборде LangSmith.

```bash
LANGSMITH_TRACING=true
LANGSMITH_ENDPOINT=https://api.smith.langchain.com
LANGSMITH_API_KEY=lsv2_pt_xxxxxxxxxxxxxxxx
LANGSMITH_PROJECT=xxx
```

#### Трассировка Langfuse

Nova также поддерживает Observability через [Langfuse](https://langfuse.com).

```bash
LANGFUSE_TRACING=true
LANGFUSE_PUBLIC_KEY=pk-lf-xxxxxxxxxxxxxxxx
LANGFUSE_SECRET_KEY=sk-lf-xxxxxxxxxxxxxxxx
LANGFUSE_BASE_URL=https://cloud.langfuse.com
```

## От Глубокого Исследования к Фреймворку Супер-Агента

Nova начался как фреймворк глубокого исследования — и сообщество пошло дальше. Разработчики использовали его для построения пайплайнов данных, генерации слайдов, создания дашбордов, автоматизации контент-процессов. Мы этого не предвидели.

Это сказало нам кое-что важное: Nova — это не просто инструмент исследования. Это **фреймворк** — рантайм, дающий агентам инфраструктуру для реальной работы.

Поэтому мы переписали его с нуля.

Nova 2.0 — больше не фреймворк для склейки. Это супер-агент фреймворк — с батарейками, полностью расширяемый. Построен на LangGraph и LangChain, он поставляет всё необходимое агенту из коробки: файловую систему, память, навыки, sandbox-осведомлённое выполнение, и возможность планировать и порождать субагентов для сложных многошаговых задач.

Используйте как есть. Или разберите и адаптируйте.

## Основные Возможности

### Навыки и Инструменты

Навыки — это то, что позволяет Nova делать *почти всё*.

Стандартный навык агента — это структурированный модуль возможностей — Markdown-файл, определяющий рабочий процесс, лучшие практики и ссылки на вспомогательные ресурсы. Nova поставляется с встроенными навыками для исследований, генерации отчётов, создания слайдов, веб-страниц, генерации изображений и видео, и многого другого. Но настоящая сила — расширяемость: добавляйте свои навыки, заменяйте встроенные, или комбинируйте в составные рабочие процессы.

Навыки загружаются постепенно — только когда задача их требует, а не все сразу. Это держит контекстное окно компактным и позволяет Nova работать даже с токен-чувствительными моделями.

Инструменты следуют той же философии. Nova поставляется с базовым набором — веб-поиск, веб-фетч, файловые операции, bash-выполнение — и поддерживает кастомные инструменты через MCP-серверы и Python-функции. Заменяйте всё. Добавляйте всё.

#### Рыночные данные и трейдинг

Группа инструментов `trading` даёт агенту реальные рыночные данные из бесплатных источников без API-ключей:

| Инструмент | Назначение |
|---|---|
| `get_ohlcv` | OHLCV-свечи — **yfinance** для акций/форекса/фьючерсов, публичные эндпоинты **ccxt** для криптовалют |
| `compute_indicators` | SMA, EMA, RSI (по Уайлдеру), MACD, ATR, ADX/DMI, полосы Боллинджера, сессионный VWAP с полосами ±kσ |
| `backtest_signals` | Проигрывает сигналы входа на реальных свечах → винрейт, матожидание в R, профит-фактор, макс. просадка |

API-ключи не нужны. Индикаторы написаны на чистом Python и работают при обычной установке;
для загрузки живых данных нужна одна опциональная зависимость:

```bash
cd backend && uv sync --extra trading    # ставит yfinance + ccxt
```

Свеча, задевшая одновременно стоп и цель, засчитывается как **убыток** — данные OHLC не позволяют
восстановить порядок цен внутри свечи, а допущение в свою пользу создаёт преимущество,
которое не воспроизведётся в реальной торговле.

О золоте: бесплатного спотового XAU/USD не существует — `XAUUSD`, `XAUUSD=X` и `XAU=X`
возвращают из Yahoo пустые данные. Используйте `GC=F` (фьючерс COMEX) или `PAXG/USDT`
через ccxt для серии, отслеживающей спот — при неверном тикере инструмент подскажет верный.

В паре с этим идёт встроенный навык **`pine-script`** для написания TradingView Pine Script v5/v6:
справочник по языку, шаблоны индикаторов и стратегий с реалистичными параметрами бэктеста
и валидатор, отлавливающий несуществующие встроенные идентификаторы до вставки в TradingView:

```bash
python /mnt/skills/public/pine-script/scripts/validate_pine.py mystrategy.pine
```

### Субагенты

Сложные задачи редко укладываются в один проход. Nova декомпозирует их.

Главный агент может порождать субагентов на лету — каждый со своим изолированным контекстом, инструментами и условиями завершения. Субагенты работают параллельно когда возможно, сообщают структурированные результаты, и главный агент синтезирует всё в связный вывод.

Так Nova обрабатывает задачи от минут до часов: исследовательская задача может разветвиться на дюжину субагентов, каждый исследует свой угол, затем сходится в один отчёт — или сайт — или презентацию с сгенерированными визуалами. Один фреймворк, множество рук.

### Песочница и Файловая Система

Nova не просто *говорит* о выполнении. У него есть собственный компьютер.

Каждая задача получает своё среду выполнения с полным представлением файловой системы — навыки, рабочее пространство, загрузки, результаты. Агент читает, пишет и редактирует файлы. Может просматривать изображения и, при безопасной настройке, выполнять shell-команды.

С `AioSandboxProvider` shell выполняется в изолированных контейнерах. С `LocalSandboxProvider` файловые инструменты маппятся на потоковые директории хоста, но `bash` хоста отключён по умолчанию (небезопасная граница изоляции).

Вот разница между чат-ботом с доступом к инструментам и агентом с реальной средой выполнения.

### Инженерия Контекста

**Изолированный Контекст Субагента**: Каждый субагент работает в своём изолированном контексте. Это значит, что субагент не видит контекст главного агента или других субагентов.

**Резюмирование**: В сессии Nova агрессивно управляет контекстом — резюмирует завершённые подзадачи, выгружает промежуточные результаты в файловую систему, сжимает то, что больше не нужно немедленно. Это позволяет оставаться острым на длинных многошаговых задачах без превышения контекстного окна.

**Строгое Восстановление Вызовов Инструментов**: Когда провайдер или middleware прерывает цикл вызовов инструментов, Nova теперь剥离 сырые метаданные вызовов инструментов уровня провайдера на принудительно остановленных сообщениях ассистента и инжектит placeholder-результаты для「зависших」вызовов перед следующим вызовом модели.

### Долгосрочная Память

Большинство агентов забывают всё при окончании разговора. Nova помнит.

Через сессии Nova строит персистентную память вашего профиля, предпочтений и накопленных знаний. Чем больше используете, тем лучше он знает — ваш стиль письма, ваш техстек, повторяющиеся рабочие процессы. Память хранится локально и остаётся под вашим контролем.

## Рекомендуемые Модели

Nova агностичен к моделям — работает с любым LLM, реализующим OpenAI-совместимый API. Тем не менее, он лучше всего работает с моделями, поддерживающими:

- **Длинные контекстные окна** (100k+ токенов) для глубоких исследований и многошаговых задач
- **Возможности рассуждения** для адаптивного планирования и сложной декомпозиции
- **Мультимодальные входы** для понимания изображений и видео
- **Сильное использование инструментов** для надёжного вызова функций и структурированных выводов

## Встроенный Python Клиент

Nova может использоваться как встроенная Python-библиотека без запуска полных HTTP-сервисов. `DeerFlowClient` обеспечивает прямой доступ в процессе ко всем возможностям агента и Gateway, возвращая те же схемы ответов что и HTTP Gateway API:

```python
from deerflow.client import DeerFlowClient

client = DeerFlowClient()

# Чат
response = client.chat("Проанализируй для меня эту статью", thread_id="my-thread")

# Стриминг (SSE протокол LangGraph: values, messages-tuple, end)
for event in client.stream("hello"):
    if event.type == "messages-tuple" and event.data.get("type") == "ai":
        print(event.data["content"])

# Конфигурация и управление — возвращает dict, выровненные с Gateway
models = client.list_models()        # {"models": [...]}
skills = client.list_skills()        # {"skills": [...]}
client.update_skill("web-search", enabled=True)
client.upload_files("thread-1", ["./report.pdf"])  # {"success": True, "files": [...]}
```

Полная документация API в `backend/packages/harness/deerflow/client.py`.

## ⚠️ Уведомление о Безопасности

### Неправильный Деплой Может Ввести Риски Безопасности

Nova обладает высокоприлегированными возможностями, включая **выполнение системных команд, операции с ресурсами и вызов бизнес-логики**, и по умолчанию спроектирован для **деплоя в локальной доверенной среде (доступ только через loopback интерфейс 127.0.0.1)**. Если вы деплоите агента в недоверенных средах — таких как LAN-сети, публичные облачные серверы или другие среды с мульти-точечным доступом — без строгих мер безопасности, это может ввести риски.

**Мы настоятельно рекомендуем деплой Nova в локальной доверенной сетевой среде.** Если нужен кросс-устройственный или кросс-сетевой деплой, необходимо реализовать строгие меры безопасности: IP-листы, аутентификационный шлюз и сетевую изоляцию.
